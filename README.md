# ניהול כספים לעסק ולמשק בית

אפליקציית ניהול כספים בעברית (RTL), בנויה Mobile-First עבור טלפון Android, עם בסיס נתונים אמיתי
(Firebase). העסק ומשק הבית מנוהלים בנפרד, וכשנטו העסק עובר למשק הבית הוא נספר פעם אחת בלבד.

> **סטטוס: סבב 1 הושלם.** הסבבים הבאים (הכנסות והוצאות, תקציב, מעשרות, חיפוש, סיכומים, גרפים,
> הגדרות, Offline) מפורטים בסוף הקובץ.

## מה כבר עובד

- יצירת חשבון, כניסה, יציאה ושחזור סיסמה (Firebase Authentication).
- מסך פתיחה, ובמכשיר מוכר: שם המשתמש מוצג ורק הסיסמה נדרשת.
- מסך הבית עם מעבר בין עסק למשק בית (החלקה או כפתור תחתון).
- שורת כותרת קבועה עם הגדרות ובחירת חודש, וכפתור "חזרה לחודש הנוכחי".
- הודעת "חודש עדיין לא התחיל" לחודש עתידי, בלי פלוס/מינוס מטעה.
- מסגרת פלוס/מינוס חודשית עם פירוט החישוב בלחיצה.
- חישוב נטו עסק והעברתו למשק הבית ללא ספירה כפולה.
- שכבת חישובים נפרדת מה-UI, עם 74 בדיקות יחידה (סכומים כאגורות שלמות, נטו, מעשרות מצטברים, תקציב,
  אחוזי שינוי).
- סכמת Firestore ו-Security Rules שמבודדים כל משתמש.
- מטמון מקומי של Firestore, כך שפעולות נשמרות במכשיר גם בלי אינטרנט.

**עדיין לא קיים:** הוספה ועריכה של הכנסות והוצאות, ולכן המסך הראשי יציג אפסים עד סבב 2.

## מה צריך להגדיר פעם אחת (בשפה פשוטה)

### 1. התקנת Node.js

מורידים את הגרסה המומלצת (LTS) מ-https://nodejs.org ומתקינים.

### 2. יצירת פרויקט Firebase

1. נכנסים ל-https://console.firebase.google.com עם חשבון Google.
2. לוחצים **Create a project**, נותנים שם, ואפשר לכבות את Google Analytics.
3. בתפריט הימני: **Build ← Authentication ← Get started ← Email/Password ← Enable ← Save**.
4. בתפריט הימני: **Build ← Firestore Database ← Create database**.
   - מיקום: מומלץ `me-west1` (תל אביב) או `eur3`. **אי אפשר לשנות מיקום אחרי היצירה.**
   - מצב: **Production mode**.
5. גלגל השיניים ליד "Project Overview" ← **Project settings** ← **General**.
   בחלק **Your apps** לוחצים על סמל ה-Web (`</>`), נותנים שם ולוחצים **Register app**.
   מופיעים ערכים כמו `apiKey`, `authDomain`, `projectId`. משאירים את החלון פתוח.

### 3. חיבור האפליקציה ל-Firebase

1. בתיקיית הפרויקט מעתיקים את `.env.example` לקובץ חדש בשם `.env`.
2. ממלאים בו את הערכים מ-Firebase:

| משתנה ב-`.env` | הערך מ-Firebase |
| --- | --- |
| `VITE_FIREBASE_API_KEY` | `apiKey` |
| `VITE_FIREBASE_AUTH_DOMAIN` | `authDomain` |
| `VITE_FIREBASE_PROJECT_ID` | `projectId` |
| `VITE_FIREBASE_STORAGE_BUCKET` | `storageBucket` |
| `VITE_FIREBASE_MESSAGING_SENDER_ID` | `messagingSenderId` |
| `VITE_FIREBASE_APP_ID` | `appId` |
| `VITE_PRIVACY_CONTACT_EMAIL` | אופציונלי: מייל ליצירת קשר במדיניות הפרטיות |

הקובץ `.env` לא עולה ל-GitHub (הוא ב-`.gitignore`). לא מדביקים אותו בשום מקום ציבורי.

### 4. העלאת חוקי האבטחה (חשוב מאוד, לפני שימוש אמיתי)

הדרך הפשוטה, בלי התקנות:

1. ב-Firebase Console: **Build ← Firestore Database ← Rules**.
2. מוחקים את התוכן ומדביקים במקומו את כל התוכן של הקובץ `firestore.rules` מהפרויקט.
3. לוחצים **Publish**.

בלי השלב הזה, Firestore במצב Production חוסם הכול והאפליקציה לא תצליח לשמור נתונים.

## הרצה מקומית

בטרמינל, בתיקיית הפרויקט:

```
npm install
npm run dev
```

הכתובת שתודפס (בדרך כלל http://localhost:5173) נפתחת בדפדפן. כדי לראות איך זה נראה בטלפון, אפשר
לפתוח את כלי המפתחים של Chrome (F12) ולבחור תצוגת מכשיר נייד.

## בדיקות ו-Build

```
npm run check
```

מריץ בבת אחת: בדיקת TypeScript, ESLint, בדיקות יחידה ו-Build.

### בדיקות חוקי האבטחה (דורשות Java)

```
npm run test:rules
```

מפעיל את האמולטור של Firestore ובודק שמשתמש אחד לא יכול לקרוא או לכתוב נתונים של משתמש אחר, ושפעולה עם
סכום או תאריך לא תקינים נדחית. הבדיקות כתובות ועוברות קומפילציה, **אך עדיין לא הורצו בפועל**, כי
האמולטור לא היה זמין בסביבה שבה נבנה הסבב הראשון. מומלץ להריץ אותן לפני שימוש אמיתי.

## פריסה (Firebase Hosting)

1. מתקינים את הכלי: `npm install -g firebase-tools`, ואז `firebase login`.
2. ב-Firebase Console: **Build ← Hosting ← Get started** (פעם אחת).
3. בתיקיית הפרויקט: `firebase use --add` ובוחרים את הפרויקט.
4. `npm run build` ואז `firebase deploy --only hosting`.

הכתובת הציבורית תופיע בסוף הפריסה. הדומיין הזה מתווסף אוטומטית לדומיינים המורשים של
Authentication.

## מבנה הפרויקט

```
src/
  domain/        חישובים וכללים עסקיים טהורים (ללא Firebase וללא UI) + בדיקות
  services/      כל הגישה ל-Firebase (התחברות, פרופיל, פעולות)
  features/      מסכים לפי נושא: auth, home, settings, privacy, month
  components/    רכיבי UI משותפים
  hooks/         Hooks משותפים
  data/          נתוני ברירת מחדל (קטגוריות)
  firebase/      אתחול Firebase ומטמון Offline
firestore.rules          חוקי אבטחה
firestore.indexes.json   אינדקסים
firebase.json            הגדרות Firebase (Rules, Hosting)
docs/ARCHITECTURE.md     ארכיטקטורה, סכמת בסיס הנתונים והחישובים
```

פירוט מלא: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## החלטות פתוחות

אלו נקודות שבהן לא ניחשתי נוסחה כספית, אלא בניתי הגדרה שאפשר לשנות:

1. **חודש הפסדי בעסק:** הוכרע. הפסד העסק עובר למשק הבית ומקטין את הכנסותיו (`allow-negative`, ברירת
   המחדל). אם בעתיד תרצה שהפסד לא יעבור, אפשר לעבור ל-`positive-only` בלי לשנות קוד חישוב.
   **מעשרות בחודש הפסדי:** ההפסד מקטין את ההכנסה החייבת המצטברת (רווח מחודש קודם מקוזז), אבל חוב
   המעשר אינו יורד מתחת לאפס, והפסד לא מוצג כ"עודף מעשרות". זו הנחה שלי, ואם הנוסחה צריכה להיות
   אחרת (למשל להתחיל חישוב מחדש בכל חודש), כדאי להגיד.
2. **מעשר שנרשם כהוצאה עסקית:** כרגע נספר כמעשר ששולם (`countBusinessTithePayments`).
3. **סטטוס מעשר בהכנסה עסקית:** השדה נשמר, אך לפי המפרט רק נטו העסק נכנס לחישוב המעשרות, ולכן
   הוא אינו משפיע כרגע.
4. **שם משתמש:** ההתחברות היא לפי כתובת מייל (כך עובד Firebase Authentication). המכשיר זוכר את
   המייל והשם הפרטי ומציג אותם בכניסה. שם משתמש נפרד דורש תשתית נוספת בתשלום.
5. **כתובת ליצירת קשר** בנושא פרטיות: יש להגדיר ב-`VITE_PRIVACY_CONTACT_EMAIL`.
