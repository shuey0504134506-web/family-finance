# ניהול כספים – תוכנה ל-Windows

פרויקט נפרד בתוך המאגר. **האתר ואפליקציית האנדרואיד לא משתנים ולא נדרסים**: כל הקוד של התוכנה נמצא בתיקייה הזאת בלבד,
והוא קורא את קוד האפליקציה (`../src`) כמות שהוא, **לקריאה בלבד**, בזמן הבנייה.

## מה זה
- אותו קו עיצוב ואותן פונקציות כמו האפליקציה, עם עיצוב שנבנה מחדש למסך מחשב: תפריט צד קבוע, תוכן רחב, מסך כניסה דו-טורי.
- **כל הנתונים נשמרים מקומית בקובץ JSON מוצפן** (תיקיית נתוני המשתמש של Windows, `%APPDATA%\ניהול כספים\data`).
- סנכרון לענן (Firebase) **רק בחשבון מקוון ורק כשיש אינטרנט**.

## סוגי חשבון
| | חשבון מקוון | חשבון מנותק |
|---|---|---|
| יצירה | דורשת אינטרנט (Firebase) | בלי אינטרנט בכלל |
| כניסה ראשונה במחשב | דורשת אינטרנט | – |
| כניסה אחר כך | בסיסמה, גם בלי אינטרנט | בסיסמה |
| סנכרון | אוטומטי כשיש חיבור | **אף פעם**, גם כשיש חיבור |
| שחזור סיסמה | מייל (Firebase) או שלוש שאלות | שלוש שאלות בלבד |

## הצפנה ושחזור סיסמה
- קובץ אחד לחשבון. התוכן מוצפן ב-AES-256-GCM במפתח אקראי; המפתח עצמו עטוף פעמיים: פעם בסיסמה (PBKDF2-SHA256, 310,000 סבבים) ופעם בתשובות לשלוש שאלות השחזור.
- שלוש שאלות, וכולן נדרשות: חלקן שהמשתמש קבע בעצמו, וחלקן **נגזרות מההוצאות וההכנסות האחרונות** (מחודשים שהסתיימו, רק כשהתשובה חד-משמעית). התשובות עצמן אינן נשמרות בגלוי.
- שאלה נגזרת מתרעננת בכל כניסה, כך שעריכה של פעולה ישנה לא נועלת את השחזור.
- **שכחתם סיסמה ואין שאלות שחזור בחשבון מנותק = אין דרך לשחזר.** זה מכוון, כי אין שרת ואין "דלת אחורית".
- שם החשבון (ולא הנתונים) נראה בקובץ האינדקס, כדי שאפשר יהיה להציג את רשימת החשבונות לפני הכניסה.

## סנכרון
- תור שינויים (outbox) נשמר בתוך הקובץ המוצפן ולכן שורד סגירה והפעלה מחדש, כמה פעמים שצריך.
- כשיש חיבור: דוחפים שינויים ממתינים, ואז מושכים מהענן ומאזינים בזמן אמת.
- כלל התנגשות: כתיבה מקומית שעוד לא עלתה גוברת; מסמך שנמחק במכשיר אחר נמחק גם כאן; בשאר המקרים הכותב האחרון מנצח (ברמת המסמך).

## פיתוח
```bash
npm ci                 # בשורש המאגר (האפליקציה המשותפת)
cd desktop && npm ci   # התוכנה
npm test               # בדיקות יחידה (כספת, שחזור, מסד, סנכרון, בקר)
npm run typecheck
npm start              # בנייה והרצה (דורש תצוגה גרפית)
```
בנייה ל-Windows: לשונית **Actions ← "בניית תוכנת Windows" ← Run workflow**. התוצאה בעמוד Releases (`desktop-v...`).
משתני Firebase נלקחים מאותם Secrets של האפליקציה (`VITE_FIREBASE_*`).

## מבנה
- `electron/` – תהליך ראשי ו-preload (גישת קבצים מוגבלת בשמות בטוחים, כתיבה אטומית).
- `src/core/` – הצפנה, כספת, שאלות שחזור, ניהול חשבונות (בלי תלות ב-Electron או ב-Firebase).
- `src/db/` – מסד מסמכים מקומי בצורת Firestore.
- `src/shims/` – תחליפים ל-`firebase/*` שהבנייה מפנה אליהם במקום ל-SDK האמיתי (האפליקציה עצמה לא משתנה).
- `src/sync/` – מנוע סנכרון ומתאם Firebase אמיתי.
- `src/ui/`, `src/styles/` – מסכי הכניסה, המעטפת והעיצוב למסך מחשב.

## מגבלות ידועות
- התוכנה **לא חתומה דיגיטלית**, ולכן Windows עשוי להציג אזהרת SmartScreen בהתקנה ("מידע נוסף" ← "הפעל בכל זאת").
- הבדיקות האוטומטיות רצות על Linux; בדיקה על Windows אמיתי נעשית ידנית אחרי הבנייה.
- מסכי הכניסה, המעטפת (תפריט הצד) ומסך הכניסה לחשבון נבנו מחדש למחשב. מסך הבית מותאם בפריסה דו-טורית. שאר המסכים (טפסים, רשימות, דוחות) הם מסכי האפליקציה עצמם, בלי שינוי, בתוך המעטפת החדשה, ולכן הם נשארים עמודה מרכזית ברוחב נוח ולא פריסה חדשה לגמרי.
- שאלות שחזור שנגזרות מהפעולות מופיעות בעברית גם כשהתוכנה באנגלית.
