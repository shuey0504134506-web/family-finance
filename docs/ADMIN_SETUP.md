# שלב 2: אישור וחסימה של חשבונות

מהשלב הזה, כל חשבון חדש ממתין לאישור שלך לפני שהוא רואה או שומר נתונים. אפשר גם לחסום חשבון.

## סדר הפרסום (חשוב, כדי שאף משתמש קיים לא ינעל)

1. **פריסת הפונקציות מחדש:** Actions ← פריסת פונקציות השרת ← Run workflow (מוסיף את האישור והחסימה).
2. **רק אחרי שהאתר התעדכן:** באפליקציה, הגדרות ← ניהול מתקדם ← **אישור כל החשבונות הקיימים** ← אישור.
   בשלב הזה הכללים הישנים עדיין פעילים, ולכן שום דבר לא נחסם.
3. **פרסום כללי Firestore:** מעתיקים את `firestore.rules` מהמאגר ל-Firebase Console ← Firestore ← Rules ← Publish (כמו בפעם הקודמת).
4. **בדיקה:** נרשמים עם אימייל חדש (אפשר כתובת בדיקה). אמורה להופיע "החשבון ממתין לאישור". בניהול מתקדם לוחצים "אישור", והאפליקציה אצל המשתמש נפתחת לבד.

אם משהו משתבש בשלב 3 ומשתמשים נעולים: מפרסמים שוב את הכללים הקודמים (Rules ← History), או מריצים "אישור כל החשבונות הקיימים".

## מה אפשר לעשות
- **אישור**: חשבון ממתין נפתח.
- **חסימה**: המשתמש מנותק ולא יכול להיכנס, והנתונים שלו נשארים. **ביטול חסימה** מחזיר אותו.
- חשבון המנהל מוגן מחסימה.

# שלב 3: דרישת תשלום לחשבון

בניהול מתקדם, בכל חשבון: **דרישת תשלום**. מגדירים:
- **מועד נעילה** (סוף היום שנבחר).
- **סכום**: טקסט חופשי, למשל "50 ₪ לחודש".
- **קישור לתשלום**: חייב להתחיל ב-https://.
- **הודעה למשתמש**: מלל חופשי.

מה קורה:
- **שבוע לפני המועד** מופיע אצל המשתמש פס תזכורת עם הסכום וכפתור "מעבר לתשלום".
- **במועד** האפליקציה אצלו ננעלת ומוצג מסך תשלום עם הסכום, ההודעה והקישור. הנתונים נשמרים. הנעילה נאכפת בכללי Firestore בשרת, ולא רק במסך.
- **אחרי שהוא שילם**: "עריכת תשלום" ← מאריכים את המועד, או "הסרת דרישת תשלום". האפליקציה אצלו נפתחת לבד.

חשוב: כדי שהנעילה בשרת תפעל, צריך לפרסם שוב את `firestore.rules` (כמו בשלב 2), ולפרוס מחדש את הפונקציות.
